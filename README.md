# URL Shortener — Backend (Steps 1–2: Setup, Schema & Core Shortening)

Step 1 built the project structure, database connection, and the three
core tables. Step 2 adds the actual shortening logic: base62 short-code
generation with collision checking, plus the `/shorten` and redirect
endpoints. No auth yet — that's Step 3.

## Project structure

```
backend/
├── app/
│   ├── __init__.py
│   ├── database.py       # DB connection, session factory
│   ├── models.py         # User, URL, Click tables
│   ├── schemas.py        # Pydantic request/response models
│   ├── shortener.py       # base62 short-code generation + collision handling
│   ├── routers/
│   │   ├── __init__.py
│   │   └── urls.py       # POST /shorten, GET /{short_code}
│   └── main.py           # FastAPI app + health check
├── requirements.txt
└── .env.example
```

## Setup

1. **Create a virtual environment**
   ```bash
   python -m venv venv
   source venv/bin/activate   # On Windows: venv\Scripts\activate
   ```

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

3. **Set up PostgreSQL**
   - Install PostgreSQL locally, or use a free hosted instance (e.g. Railway, Supabase, Neon).
   - Create a database, e.g. `url_shortener`.

4. **Configure environment variables**
   ```bash
   cp .env.example .env
   ```
   Then edit `.env` and set your real `DATABASE_URL` (and later, `JWT_SECRET_KEY`).

5. **Run the server**
   ```bash
   uvicorn app.main:app --reload
   ```

6. **Verify it works**
   - Visit `http://localhost:8000/` → should return a welcome message
   - Visit `http://localhost:8000/health` → should return `{"status": "ok", "database": "connected"}`
   - Visit `http://localhost:8000/docs` → interactive Swagger UI (auto-generated by FastAPI)

   On first run, `Base.metadata.create_all()` will automatically create the
   `users`, `urls`, and `clicks` tables in your database.

## Schema overview

| Table  | Purpose                                                        |
|--------|-----------------------------------------------------------------|
| users  | Registered users who create and manage short links             |
| urls   | Maps a `short_code` to the `original_url`, linked to an owner  |
| clicks | One row per redirect — powers the analytics dashboard later     |

## Trying the shortener (Step 2)

With the server running (`uvicorn app.main:app --reload`):

**Shorten a URL**
```bash
curl -X POST http://localhost:8000/shorten \
  -H "Content-Type: application/json" \
  -d '{"original_url": "https://www.example.com/some/very/long/path"}'
```
Response:
```json
{
  "short_code": "aZ9kLp",
  "original_url": "https://www.example.com/some/very/long/path",
  "created_at": "2026-09-14T05:14:29.737830"
}
```

**Use the short link** — visiting it redirects (HTTP 307) to the original URL:
```bash
curl -i http://localhost:8000/aZ9kLp
```

Or just open `http://localhost:8000/docs` and try it in the Swagger UI.

### How short codes are generated
`app/shortener.py` picks a random 6-character base62 string
(`a-zA-Z0-9`, ~56.8 billion combinations) and checks the database to make
sure it isn't already taken, retrying a few times on the rare chance of a
collision. This is a simpler alternative to encoding an auto-increment ID —
worth knowing both approaches for interviews, since it's a common
system-design talking point.

### ⚠️ Route ordering gotcha
`GET /{short_code}` is a catch-all path. It's registered in `main.py`
**after** `/` and `/health`, otherwise it would swallow those requests too
(Starlette/FastAPI matches routes in registration order — see the comment
above `app.include_router(...)` in `main.py`). Worth remembering for any
API with a catch-all path parameter.
